# Bug hunt statique — chaîne 3D (plugin, kext, device, cœur, backends), 22/09/2026

Objectif : que la 3D OpenGL de Tiger tourne à fond et sans plantage sous QEMU PPC.
Méthode : relecture statique intégrale par sept relecteurs indépendants (un par
couche), chaque finding recroisé avec la couche d'en face (plugin ↔ cœur, kext ↔
device, GL ↔ soft). Rien n'a été exécuté dans l'invité ; **le cœur et le backend
logiciel ont été compilés et exécutés en natif** (harnais du dépôt + ~3,2 millions
de commandes fuzzées sous ASan/UBSan/LSan : zéro plantage, zéro fuite).
Les findings marqués **[V]** ont été revérifiés à la main dans le source par le
coordinateur. Aucun fichier de code n'a été modifié : ce document est le
livrable, les correctifs sont proposés mais pas appliqués — ils demandent la VM.

État du harnais sur HEAD (`23a441e`) : `./tests/run-all.sh` → **71 OK, 1 échec**
(`qgpu_core_test`, cas `(n) ALPHA`, voir H1). Ce rouge date du commit `f3c4280`.

## 1. Plantages et corruptions mémoire

### Kext `POMPPCGPU` (`kext/POMPPCGPU/POMPPCGPU.cpp`)

- **K1 CRITIQUE [V]** — *corrigé le 22/09/2026* `:720` — `POMPPCGPUUserClient::stop()` ne remet pas `fOwner` à 0 et ne rend
  pas la tranche. Terminaison par le haut (`kextunload`, `terminate`) avec un client ouvert : le
  prochain `SUBMIT` passe `if (!fOwner)` et déréférence une gate et un `IOMemoryMap` déjà libérés.
  Fix : `if (fOwner && fSlot >= 0) { fOwner->freeSlot(fSlot); fSlot = -1; } fOwner = 0;` avant
  `super::stop`.
- **K2 CRITIQUE [V]** — *corrigé le 22/09/2026* `:424-448` — `SubmitArgs a` non initialisée et retour de `runAction` ignoré.
  Si l'action ne s'exécute pas (gate retirée par `stop()`), on rend au userland 3 mots de pile
  noyau et un `fence` aléatoire → `ucWaitFence` jusqu'à 60 s en `THREAD_UNINT`. `waitFence` et
  `allocSlot` pré-initialisent leurs `Args`, seul `submit()` ne le fait pas.
- **K3 CRITIQUE [V]** — *corrigé le 22/09/2026* `:725-739` + `:566-586` — `clientClose` et `clientDied` peuvent courir
  (processus tué pendant un dessin, 2 vCPU) : `fSlot >= 0` testé, `freeSlot` bloquant ~1 s,
  `fSlot = -1` après. Double `freeSlot(n)` ; entre les deux, `allocSlot` a pu redonner la tranche
  à un autre processus, dont `slotGated` détruit alors les objets sans vérifier
  `fClients[slot] == client`. Deux processus finissent sur la même tranche.
- **K4 CRITIQUE** — *corrigé le 22/09/2026* `:154-183` vs `:474-504` — `stop()` retire IRQ et timer sans réveiller les
  dormeurs de `waitGated` (`commandSleep` `THREAD_UNINT`, seules sources de réveil : IRQ et timer).
  Gel inkillable, puis `free()` relâche gate et workloop sous un dormeur → panic. Systématique en
  boucle de dev (`kextunload` avec un jeu ouvert). Fix : drapeau `fStopping` + `commandWakeup`
  dans `stop()`, testé avant chaque `commandSleep`.
- **K5 MAJEUR** — *corrigé le 22/09/2026* `:545-556`, `:625-661` — `destroyClientObjects` dans la gate : `drainQueue` =
  jusqu'à 1 s d'`IODelay` actif sur la file *globale*, puis **212 doorbells synchrones** (16+128+64+4
  objets), chacun tenant le BQL de QEMU (voir D2). Les 3 autres clients et tout MMIO d'un autre
  vCPU attendent : le bureau se fige à chaque sortie d'application 3D. Fix : destructions
  asynchrones par paquets de `QGPU_QUEUE_DEPTH` + une seule barrière, hors gate.
- **K6 MAJEUR [V]** — *corrigé le 22/09/2026* `:118` / `POMPPCGPU.h:119` — `caps()` rend `fCaps` brut ; si `fTimer` a
  échoué, `fAsync = 0` mais `QGPU_CAP_ASYNC` reste annoncé. Le plugin passe en asynchrone contre un
  kext synchrone : statut/PC confondus, et sur `st != OK` le plugin **resoumet le même flux** →
  trame exécutée deux fois. Fix : `return fAsync ? fCaps : fCaps & ~QGPU_CAP_ASYNC`.
- **K7 MAJEUR** — *corrigé le 22/09/2026* `:813-823` — `ucReset` : `allocSlot` rend la *première* tranche libre, pas celle
  que le client a mappée. Flux écrit dans l'ancienne tranche, offsets de la nouvelle. Latent (aucun
  appelant), mais sélecteur public.
- **K8 MAJEUR** — *corrigé le 22/09/2026* `:630-652` — le flux de destruction est écrit dans la première page de la tranche
  du client (vivante dans les cas K3/K7). Utiliser une page de service hors tranches.
- **K9 MAJEUR** — *corrigé le 22/09/2026* `:445`, `:521`, `:592`, `:600` — retours de `runAction` ignorés ; un `freeSlot`
  non exécuté = tranche perdue pour toujours = « 5e client refusé ».
- **K10 MAJEUR** — *corrigé le 22/09/2026* `:527-538` — repli `IOSleep(1)` × 60 000, non interruptible. Plafonner à 1–2 s et
  laisser le userland reboucler.
- Mineurs : `start()` échoue sans `super::stop()` (`:705-718`) ; retour de `commandSleep` ignoré
  (`:498`) ; framebuffers liés jamais déliés à leur terminaison (`:279`) ; `go.sh:164` écrit sur
  `/` sans `mount -uw` en single-user.

### Plugin `GLDriver-POMPPC` (`guest/gldriver/pomppc_accel.c`)

- **P1 CRITIQUE [V]** — *corrigé le 22/09/2026 (garde intérimaire : `w·bpp % 4 ≠ 0` refusé, stencil compris ; `CTX_PACK_*` toujours à relever)* `:7067-7175` — `try_read_pixels` fabrique son propre pas et ignore
  `GL_PACK_ALIGNMENT/ROW_LENGTH/SKIP_*` (les offsets `CTX_PACK_*` ne sont pas relevés, seuls les
  `CTX_UNPACK_*` le sont, `:76-80`). Stencil écrit serré alors que le défaut GL est align 4 (image
  décalée sans que l'appli ait rien réglé) ; RGB écrit aligné 4 alors que l'appli a mis align 1
  (SDL, captures) → jusqu'à `3·(h−1)` octets au-delà du tampon. `GL_RGBA` est indemne, d'où le
  silence en test. Fix : relever `CTX_PACK_*` ; en attendant refuser tout format où `w·bpp % 4 ≠ 0`.
- **P2 CRITIQUE [V]** — *corrigé le 22/09/2026* `:7455-7500` — `try_draw_pixels` couleur ignore `GL_UNPACK_*` (align 4 codé
  en dur) alors que `try_draw_ds` et `try_bitmap` les lisent. Image oblique + lecture hors du
  tampon source.
- **P3 CRITIQUE [V]** — *corrigé le 22/09/2026* `:4670-4682` — chemin `refuse:` de `geom_begin` : `ns = 65536 / (geom_words·4)`
  plafonné à 1024, mais on est précisément dans le cas où le pas de GLEngine diffère du nôtre
  (`gctx+0x4880 = 0x100`) : GLEngine écrit `1024 × 256 = 256 Kio` dans `geom_scratch[64 Kio]`.
  Atteignable avec `POMPPC_GL_ARRAY=2` ou toute divergence de descripteur. Fix :
  `ns = sizeof(geom_scratch) / GLD_VERTEX_SIZE` (256), point.
- **P4 CRITIQUE [V]** — *corrigé le 22/09/2026* `:2218-2239` — `tex_lv0_sig` : `n = w·h` **texels** utilisé comme index
  d'**octet** (`d[n/2]`, `d[n−1]`). RGBA8 : sous-lecture inoffensive ; DXT1 (0,5 o/texel) : lecture
  à 2× la taille du niveau, 512 Kio au-delà sur 1024². Appelé à chaque dessin par
  `texture_uploadable`. Bus error sur UT2004. Fix : taille réelle en octets (`dxt_bytes` /
  `LV_ROWPIX × h × host_texel_bytes`).
- **P5 CRITIQUE [V]** — *corrigé le 22/09/2026* `:6506` — `gl_note()` : `fopen("/tmp/pomppc-gl.log","a")` sans variable
  d'environnement, appelé au chargement (`:1099`, donc dans le WindowServer et loginwindow, root),
  à chaque `gldAttachDrawable` (`:7969`) et toutes les 5 s (`:617`). `/tmp` est 1777 : lien
  symbolique → écriture root arbitraire. Fix : `POMPPC_GL_NOTE=<chemin>`, ouvert une fois,
  `O_EXCL|O_NOFOLLOW`.
- **P6 MAJEUR [V]** — *corrigé le 22/09/2026* `:4199-4213` — `geom_publish` : `ent[8]` pour 9 entrées possibles
  (position, normale, couleur, secondaire, brouillard, tex0–3). Débordement de pile avec
  `COLOR_SUM` + coord. de brouillard + texgen sans éclairage + 4 unités, ou `POMPPC_GL_GEOM=2`.
  Fix : `ent[10]`.
- **P7 MAJEUR** — *corrigé le 22/09/2026* `:7698-7704` — `abort()` si `find_ctx` échoue ; or `pomppc_context_destroyed`
  (`:7882`) libère la `PCtx` **sans désinstaller les trampolines** de `procs[]` (seul
  `gldUpdateDispatch` le fait), et `gldDestroyContext` l'appelle *avant* le destructeur d'Apple.
  Tout rappel de rastérisation → `abort()`. Fix : restaurer `procs[k] = p->real[k]` avant de
  libérer ; jamais d'`abort()` dans un pilote ; `if (G.bound == p) G.bound = 0`.
- **P8 MAJEUR** — *corrigé le 22/09/2026* `pomppc_gld.c:341-366` — pas de `pthread_atfork` : l'enfant d'un `fork()` sans
  `exec` (Safari/WebKit) hérite tranche, port Mach et `G` entier, et écrit le même flux que le
  père. Fix : handler enfant qui pose `G.state = -1` et oublie port/mapping.
- **P9 MAJEUR** — *corrigé le 22/09/2026* `:1290-1306` — `broken_all` sur `BAD_ARG` : l'hôte fait `break` (H4), donc toutes
  les `SET_STATE`/`SET_MATRIX`/`TEX_IMAGE3` après la commande fautive sont perdues, mais le miroir
  (`st_valid`, `prm_valid`, `g_sent`, `c_*`, `G.bound`) n'est pas invalidé → image fausse
  **durable**. Explique le `TEX_DESTROY BAD_ARG` à la sortie noté dans `docs/re/ut2004-demo.md`.
  Fix : invalider tous les caches dans les trois branches.
- **P10 MAJEUR [V]** — *corrigé le 22/09/2026* `:1705-1740` — `pomppc_texture_deleted` : `close_run()` sans `close_raw()`
  puis écriture à la main ; c'est `flush()` qui fermera la série brute, donc le `DRAW_RAW` ouvert
  est émis **après** le `TEX_DESTROY` qu'il utilise. Fix : `reserve()`.

## 2. Image fausse (silencieuse)

### Cœur (`patches/qgpu/qgpu-core.c`)

- **H1 MAJEUR [V]** — *corrigé le 22/09/2026* `:516`, `:2249`, `:2263` (commit `f3c4280`) — `GL_ALPHA` dépaqueté en

  `REPLACE`/`ADD`/`BLEND`/`COMBINE` (blanc au lieu de la couleur primaire). Le backend soft gère

  du harnais est rouge depuis. Le contournement visait le backend GL (`qgpu-gl.c:830`) : c'est là
  qu'il faut le faire (`GL_ALPHA` en format interne — valide en profil compat, ou RGBA + table 3.22
  côté GL), et revenir à `argb(a,0,0,0)` dans le cœur.
- **H2 MAJEUR [V]** — *corrigé le 22/09/2026* `:538-549` — depuis v14 `tex_src` accepte `GL_RGBA` **et** `GL_BGRA` pour
  `4_4_4_4`, `5_5_5_1`, `4_4_4_4_REV`, `1_5_5_5_REV`, mais les quatre `case` d'`unpack_texel`
  n'examinent pas `s->fmt` (contrairement à `0x8035`/`0x8367`). BGRA+4444, RGBA+4444_REV,
  BGRA+5551, RGBA+1555_REV → R et B échangés. Le plugin (`host_texel_bytes`, `:1775`) laisse
  passer les 8 couples ; le test n'exerce que les 4 bons.
- **H3 MINEUR** — *corrigé le 22/09/2026* `:1174` — `unpack_rgb1555` rend alpha = 0 ; `pack_rgb1555` jette le bit 15.
  `SURF_UPLOAD` 1555 (`sync_to_host` en milliers de couleurs) → surface entièrement transparente :
  `DST_ALPHA`/`ONE_MINUS_DST_ALPHA` inversés, `COPY_TEX` invisible, relecture `00RRGGBB`.
  Fix : `0xFF000000 |`. Le test v15 utilise `px()` qui masque l'alpha.
- **H4 MAJEUR** — *corrigé le 22/09/2026* `:1247-1255`, `:1378-1387`, `:2541-2545` — NaN/±1e9 dans **n'importe quel** mot

- Mineurs : `SURF_CREATE` renseigne la case avant l'appel backend ; `QUERY_BEGIN` pose `used`

- **S-C1 CRITIQUE** — *corrigé le 22/09/2026* `mac_newworld.c` (absent du patch) — `SPR_PIR` vaut **0 sur les deux cœurs**
  (`register_74xx_sprs` : valeur par défaut 0, seul `spapr` la pose) et le firmware livré fait

- **S-C2 CRITIQUE [V]** — *corrigé le 22/09/2026* `qemu-mac99-cpus-v2.patch:82-92` — `cpu_kick()` fait `cpu_reset()` +
  `ppc_cpu_do_system_reset()` sur le CPU 1 **depuis le thread du CPU 0** (`macio_gpio_write`),

  static void cpu_kick(void *opaque, int n, int level)
  {   if (level) async_run_on_cpu(CPU(opaque), cpu_kick_work, RUN_ON_CPU_NULL); }
