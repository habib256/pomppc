# Bug hunt — toutes couches, 29/09/2026

Six relecteurs indépendants (un par couche), en lecture seule, sur HEAD `8af9efc`,
centrés sur ce qui a changé depuis le bug hunt du 22/09 (`23a441e`,
docs/bug-hunt-2026-09-22.md, dont aucun finding n'est répété ici). Puis un
agent de correction par couche, sur des fichiers disjoints. Les findings ont
été revérifiés dans le source avant correction ; ceux marqués **[R]** ont été
reproduits sur l'hôte.

**Rien de ce qui suit n'a tourné dans la VM.** Le kext et le plugin ne se
construisent que dans Tiger (gcc-4.0) : ils ne sont pas compilés. Le cœur,
`qgpu-gl.c`, `qgpu-pci.c`, les patches QEMU et le frontend sont compilés sur
l'hôte ; `tests/run-all.sh` est vert.

Laissés de côté le jour même, **corrigés ensuite (reste du 29/09)** :

| # | Quoi | Correctif |
|---|---|---|
| R1 | poignées ARB factices (`PPROG_HANDLE+i`) passées au GLDriver d'Apple après la destruction du contexte créateur (groupe de partage), ou désignant un programme recréé dans la même case | l'entrée devient **orpheline** (`ctx = 0`, invisible des parcours) et garde la poignée d'Apple jusqu'au `gldDestroyPipelineProgram` ; la case n'est pas réutilisée avant |
| R2 | ≥ 3 fils GL : `flush()` pouvait rendre la main avec `G.halt > 0` (un `drain_all`/`wait_half` direct entré pendant l'attente de `switch_half`) ; le `stream_ready()` du `reserve()` suivant relâchait `G.mu`, un tiers vidait le flux, l'offset d'arène déjà calculé désignait une moitié soumise (M1) | `wait_half_ex` n'admet **qu'un attendant verrou relâché** (entrée sans lever `halt`) ; `reserve`/`arena_alloc` constatent la place en boucle, verrou tenu, sans attente en cours |
| L1 | délai de barrière : `wait_half_ex` rendait la moitié à l'écriture sans barrière atteinte (M3) | **quarantaine** : on réattend ; au bout de `WAIT_GIVEUP`, `stream_dead()` — la moitié n'est jamais rendue, flux détourné vers un tampon privé, `G.state = -1` |
| R3 | `crash_handler` et rappels `pthread_atfork` laissés dans une image démappée par `NSUnLinkModule` | gestionnaire précédent remis dans `pomppc_backend_fini` (+ destructeur de module), plus de réarmement ; atfork posé au **premier contexte** (plugin retenu par GLEngine), et un enfant de `fork()` antérieur est reconnu au pid |
| R4 | = P7 : noms d'uniforms composés | `QGPU_CAP_GLSL_PATHS` (cœur, grammaire stricte), plugin : seul le `[0]` final est retiré |
| R5 | `QGPU_ST_LIMIT` du plafond mémoire fatal pour le lot et pour l'accélération du processus | `QGPU_ST_NO_MEM` (11) **non fatal**, mises à jour d'objets refusés tolérées, `QGPU_REG_NOMEM` ; plugin : objet non résident (texture → Apple, tampon → empaquetage, surface sondée → Apple) pendant 120 images, puis nouvel essai |

Reste à valider dans la VM pour R1–R5 : Colin McRae (contextes partagés),
trois fils GL, `kextunload` après un rejet de plugin, un shader à `uniform
struct`, `QGPU_MEM_MB=512` avec DOOM 3.

C2 : plafond par défaut = moitié de la RAM physique au total, trois quarts de ce
total par tranche ; `QGPU_MEM_MB` fixe un autre total. Au-delà : `QGPU_ST_NO_MEM`
(non fatal depuis le reste du 29/09, voir R5 ; d'abord `QGPU_ST_LIMIT`, fatal).
C1–C4 ont des cas de non-régression (`run_fix0929` dans
`tests/qgpu_core_test.c`), R4–R5 aussi (`run_reste0929`), soft et GL.

Fuzz structuré sous ASan/UBSan (≈ 5,8 M exécutions avant correctifs, ≈ 0,2 M
après, soft et GL réel) : aucune corruption mémoire hôte, compteur mémoire
revenu à 0 après destruction de toutes les tranches.
